# Phase 04.1: Redesign Aurora técnica - Research

**Researched:** 2026-10-15
**Domain:** Redesign visual de site Astro 7 estático (tokens CSS, Fonts API, motion hand-rolled CSS+IO, CSP-safe), sem regressão de Lighthouse/a11y
**Confidence:** HIGH para stack/arquitetura (código lido + CONTEXT/UI-SPEC/skill); MEDIUM para riscos de LCP com reveal do H1 (precisa de medição)

## Summary

A fase é um redesign de apresentação sobre uma base técnica que já está certa: Astro 7.3.8 `output: 'static'` + `@astrojs/vercel`, Fonts API com `fontProviders.fontsource()`, `build.inlineStylesheets: 'never'`, um único bundle `effects.ts` + `<script is:inline>` de `.js-ready`, gate de `style=` em `scripts/security-check.sh`, budget de JS 20 KB gz em `scripts/js-weight-check.sh` e gate Lighthouse (`lighthouserc.json`: perf/a11y/bp ≥0.95, LCP ≤2500, CLS ≤0.05, TBT ≤200). Nada de dependência nova é necessário para o produto; toda a trama de movimento do sketch (IO + rAF + CSS) cabe em ~2–3 KB gz, e remover `particles.ts`/`glow.ts` libera orçamento.

Os pontos que realmente exigem cuidado de planejamento são: (1) o H1 é provavelmente o LCP e o sketch o esconde (`opacity:0`) até JS adicionar `.in`: o reveal do hero deve ser guiado por **CSS animation disparada no primeiro paint**, não por IO/JS; (2) o sketch usa `style="--d:..."` e `style.setProperty` em loop: o primeiro é proibido pelo gate, o segundo (CSSOM) é permitido pela CSP, mas o split de palavras deve ser feito **em build** (componente Astro) com classes `.i0..iN`; (3) `overflow-clip-margin` (máscara de palavra) **não existe no Safari** — usar padding-bottom + margem negativa; (4) `container-type:inline-size` em `.site` faz o wrapper virar containing block de descendentes `position:fixed` e as unidades `cqi` só resolvem dentro dele — header/footer/main precisam estar dentro de `.site` e as páginas secundárias hoje **não têm header/footer** (D-15 exige adicioná-los); (5) CSS scroll-driven (`animation-timeline`) não é Baseline (Firefox desativado) — manter o `--p` por rAF do sketch como caminho único.

**Primary recommendation:** Reescrever em ondas: tokens+fontes+BaseLayout (`.site`, header/footer compartilhados) → componentes estáticos sem motion → camada de motion (`.js-ready`-gated) → conteúdo/schema (cases union, remover FAQ) → captura Playwright → gates (build, lhci, Playwright overflow/tap/reduced-motion, security-check) → polish. Hero com CSS animation pura; todo stagger por classes geradas em build; um único `effects.ts` (~100 linhas) com IO + 1 scroll listener rAF.

## Architecture Patterns

### Diagrama de fluxo

```
BUILD (astro build)
 content/*.yaml,*.md --Zod strict--> Collections --(services,process,differentiators,cases)--> componentes .astro
 Words.astro: "texto" --split por espaço--> <span.w.iN><span>palavra</span></span>   (stagger = classe, não style=)

                │

BROWSER

 .js-ready presente + prefers-reduced-motion:no-preference:
    hero: CSS animation (aurora acende, palavras do H1, lead/CTAs/prova por animation-delay em classes)  ← não depende do bundle
    bundle effects.js:
       IO#1 reveal [data-r] → +.in (seções, cards, serviços, contato)         [unobserve após disparo]
       IO#2 pai da foto → +.in no figure (clip-path)                           [observar o PAI]

```

### Pattern 1 — Fonts API (3 famílias)
```js
fonts: [
  { provider: fontProviders.fontsource(), name: 'Sora', cssVariable: '--font-display',
    weights: [600], styles: ['normal'], subsets: ['latin'], fallbacks: ['system-ui','sans-serif'],
    optimizedFallbacks: true, display: 'swap' },
  { provider: fontProviders.fontsource(), name: 'Inter Tight', cssVariable: '--font-sans',
    weights: [400, 500, 600], styles: ['normal'], subsets: ['latin'], fallbacks: ['system-ui','sans-serif'],
    optimizedFallbacks: true, display: 'swap' },
  { provider: fontProviders.fontsource(), name: 'JetBrains Mono', cssVariable: '--font-mono',
    weights: [400], styles: ['normal'], subsets: ['latin'], fallbacks: ['ui-monospace','monospace'],
    optimizedFallbacks: true, display: 'swap' },
]
```
```astro
<Font cssVariable="--font-display" preload={[{ weight: 600, style: 'normal' }]} />
<Font cssVariable="--font-sans" preload={[{ weight: 400, style: 'normal' }]} />
<Font cssVariable="--font-mono" />
```
- Estrutura espelha o código atual validado (Outfit/DM Sans) [VERIFIED: astro.config.mjs + BaseLayout]. O `<Font>` para mono é obrigatório mesmo sem preload, para emitir `@font-face`.
- `subsets: ['latin']` cobre pt-BR (ç, ã, é etc. estão em Latin/Latin-1: `U+0000-00FF`) [VERIFIED: unicodeRange latin do fontsource inclui `U+0000-00FF`].
- Preload só do LCP: Sora 600 (H1) e Inter Tight 400 (lead). Preload extra de fonte compete com CSS/LCP em mobile throttled.
- `security-check.sh` check 3 só admite `@font-face` e `:root{--font-*}` inline; 3 fontes não quebram isso. `--font-sans`/`--font-display`/`--font-mono` devem ser os únicos `cssVariable`; **remover** `--font-heading/--font-text/--font-body` de `tokens.css` e atualizar todos os consumidores (`grep -rn "font-body\|font-text\|font-heading" src`).
- Verificar após o build que `dist` não referencia `fonts.googleapis`/`gstatic` e que `<link rel=preload as=font>` aponta para `/_astro/fonts/…` [VERIFIED approach; Fonts API estável desde Astro 6, CLAUDE.md].

### Pattern 2 — Hero sem dependência de JS (protege LCP)
O H1 é o candidato natural a LCP (maior bloco de texto acima da dobra; a aurora é gradiente, que o Chrome **não** conta como candidato de LCP — **[ASSUMED]** com base no comportamento conhecido de `background-image` gradient; confirmar na medição do lhci). Chrome não conta elementos com `opacity:0` como LCP candidates até ficarem visíveis, então qualquer atraso para iniciar o fade empurra o LCP. Recomendação:
```css
@media (prefers-reduced-motion: no-preference) {
  html.js-ready .hero .w > span {
    animation: word-in .9s var(--ease-out) both;
    animation-delay: calc(var(--i) * 55ms);
  }
}
@keyframes word-in { from { transform: translateY(105%); filter: blur(8px); opacity: 0 } }
.i0 { --i: 0 } .i1 { --i: 1 } /* …até o maior H1/H2 (≈ .i24) */
```
- Sem delay global antes da 1ª palavra (o sketch espera 250 ms por `setTimeout`; em CSS não há necessidade). Aurora: `animation: lit 1.8s`.
- Lead/CTAs/prova: `animation-delay` por classes `.d520`, `.d680`, `.d820` (valores do sketch) — nunca `style=`.
- `animation-fill-mode: both` + keyframe só com `from` deixa o estado final = estilo normal; se CSS animation não rodar, o texto fica visível (degradação segura).
- Acompanhar no lhci: LCP atual ~1,5 s (STATE/case); orçamento 2,5 s. Se LCP regredir >300 ms, encurtar para `opacity` 0.35 s na 1ª palavra ou deixar o H1 inteiro com `opacity:1` e animar só `transform`/`blur` (blur+translate não afetam elegibilidade de LCP).

### Pattern 3 — Stagger/delay sem `style=` (gate)
Tabela de decisão:
| Necessidade | Solução CSP-safe | Observação |
|---|---|---|
| Índice de palavra / item de lista conhecido em build | Classe `.iN` (`--i:N`) gerada em `Words.astro` / `{items.map((x,i)=> <li class={`svc i${i}`}>)}` | Zero JS, zero `style=` |
| Delays fixos por papel (lead +520, CTAs +680, prova +820) | Classes utilitárias `.d200 .d300 .d520 .d680 .d820` | Valores dos sketch |
| Valor contínuo em runtime (`--p` do método, `--screen-h`) | `el.style.setProperty('--p', v)` (CSSOM) | CSSOM não é bloqueado por `style-src-attr`; só atributo `style` em markup e `setAttribute('style')` são [CITED: W3C CSP3 `style-src-attr`; MDN CSP style-src-attr]. O gate `grep` (`style\s*=\s*["']`) não casa `style.setProperty` |
| `aspect-ratio`, `margin:0`, `align-self` inline do sketch | Classes CSS | 17 `style=` no sketch; todos viram classe |
- **Proibido:** `style={...}` do Astro, `define:vars` (emite `style=`), `class:list` com valores dinâmicos de CSS, SVG com `style=`.
- Para `stroke-dashoffset` nos ícones: usar `pathLength="1"` + `stroke-dasharray:1` (atributos de apresentação, não `style`) em vez do hard-code `160` do sketch.

### Pattern 4 — Máscara palavra a palavra sem Safari quebrado
`overflow-clip-margin` **não é suportado no Safari** (caniuse lista Safari 3.1–26.5 e iOS sem suporte) [CITED: caniuse.com/mdn-css_properties_overflow-clip-margin]; `overflow:clip` sim (Safari 16+). Sem o margin, descendentes de Sora (p, g, ç) são cortados.
```css
.w { display: inline-block; overflow: clip; vertical-align: top;
     padding-bottom: .14em; margin-bottom: -.14em; }
.w > span { display: inline-block; }
```
- `padding-bottom` + `margin-bottom` negativo preserva a caixa de linha e funciona em todos os browsers. `overflow-clip-margin` pode ser omitido (sem comentários no código).
- O texto acessível: spans inline-block separados por espaço literal mantêm a leitura de tela por palavra; não usar `aria-label` duplicado nem `aria-hidden` nas palavras.
- `text-wrap: balance` continua funcionando (linha de inline-blocks).
- `will-change` somente durante a animação (via classe removida no `animationend`) ou nenhum — 20+ camadas promovidas permanentemente custam memória no mobile.

### Pattern 5 — Aurora sem `filter:blur`, performance
```css
.aurora { position:absolute; pointer-events:none; z-index:-1; left:-15%; right:-15%; top:-30%; height:1100px;
  opacity:var(--aurora-opacity); background: /* 3 radial-gradients da skill */ }
```
- Gradientes estáticos são rasterizados uma vez; o `drift` anima só `transform` na própria camada (compositor, sem main thread → não afeta TBT). `will-change: transform` apenas no elemento da aurora (1 camada ~ largura×1100 px; aceitável).
- **Pausar fora da tela**: IO no hero alterna `animation-play-state` (classe `.paused`), como no sketch.
- `.hero { position:relative; isolation:isolate }` — `z-index:-1` precisa de stacking context ou a aurora vai para trás do `body`.
- **Grão**: o sketch usa `.site::after` full-size com SVG `feTurbulence` em **data URI** + `mix-blend-mode:overlay`. Dois problemas: (a) um overlay `mix-blend-mode` do tamanho da página inteira (`inset:0` em `.site`) obriga mistura em toda repintura e é caro em mobile; (b) o `data:` em `url()` exige `img-src data:` na CSP da Fase 7 (CLAUDE.md pede CSP restritiva). **Prescrição:** servir o grão como arquivo same-origin (`public/grain.svg`, referenciado por `url(/grain.svg)`), aplicar `position:absolute` apenas sobre hero e contato (não full-page `fixed`), sem `mix-blend-mode` se o lhci mostrar custo (usar opacidade `.07` normal). Vite inlina assets <4 KB como data URI por padrão — por isso o arquivo em `public/` (não importado) é o caminho seguro.
- `backdrop-filter` (header rolado, form, painel mobile): limitar às 3 superfícies da UI-SPEC; aplicar blur do header só na classe `.scrolled`; em `@supports not (backdrop-filter…)` usar fundo mais opaco (`rgba(7,10,20,.92)`).

### Pattern 6 — Linha do método e header (um listener)
```ts
let ticking = false;
const onScroll = () => {
  ticking = false;
  header.classList.toggle('scrolled', scrollY > 24);
  /* p = clamp((vh*.85 - r.top)/(vh*.55)); steps.style.setProperty('--p', p.toFixed(3)); toggle .lit por etapa */
};
addEventListener('scroll', () => { if (!ticking) { ticking = true; requestAnimationFrame(onScroll); } }, { passive: true });
```
- `getBoundingClientRect()` só no `.steps` (1 leitura por frame); escrever `--p` no `.steps` (escopo mínimo de recálculo).
- Sem JS / reduced-motion: `--p:1` default em CSS e todas as etapas `.lit` (texto 1, nó colorido). Estado "apagado" (`opacity .3`) só sob `html.js-ready` + `no-preference`.
- Mobile (≤560 px container): linha vertical `scaleY(var(--p))`.

### Pattern 7 — Foto com clip-path
Observar o **pai** (`figure`/wrapper) com IO e adicionar `.in` ao elemento recortado; um elemento totalmente recortado por `clip-path:inset(100% 0 0 0)` não intersecta e o IO nunca dispara [CITED: skill movimento.md; comportamento do IO documentado]. Fallback: o timeout global de ~2,6 s revela tudo na viewport. `clip-path`+`transform` não geram CLS. Reduced-motion: `clip-path:none`, só `opacity`.

### Pattern 8 — Browser frame com scroll sem JS de medição
O sketch usa `--screen-h` (provavelmente medido por JS). Alternativa sem JS: tornar `.screen` um container de tamanho (`container-type:size` com `aspect-ratio` definido) e animar `translate: 0 calc(-100% + 100cqh)` — `%` refere-se à altura do próprio elemento (imagem/mock) e `100cqh` à altura do `.screen` **[ASSUMED]** (comportamento padrão de CSS; validar visualmente). Play/pause: IO alterna `.run`; `.card:hover .scroller{animation-play-state:paused}`; reduced-motion: `animation:none`. Imagem da captura: `<Picture loading="lazy" decoding="async" widths/sizes>` com `width/height` explícitos (sem CLS).

### Anti-Patterns
- **Esconder o H1 via JS** (`.js [data-r=words] … opacity:0` até `.in`): atrasa LCP e quebra se o bundle falhar.
- **`:hover{padding-left:10px}` nos serviços** (UI-SPEC): `padding` causa layout e viola ANIM-09; usar `transform:translateX(10px)` nos filhos (mesmo visual).
- **`overflow:hidden` em `.site`**: quebra `position:sticky` (usar `overflow:clip`).
- **Sticky do intro de Serviços com `top:32px`**: o header sticky (68 px) cobre; usar `top: calc(68px + 32px)`.
- **Tilt com `will-change:transform` em todos os cards permanentemente**: aplicar só em `@media (pointer:fine) and (prefers-reduced-motion:no-preference)` e no `:hover`.
- **`scroll-behavior:smooth`** global sem `@media (prefers-reduced-motion:reduce){auto}` (ANIM-08, já existe).
- Qualquer lib de animação (bloqueada pelo `js-weight-check.sh`).

## Common Pitfalls

### 1. LCP regride por reveal do hero (maior risco de perf)
**What:** H1/lead com `opacity:0` até JS. **Why:** candidato LCP só conta quando visível; bundle é `type=module` (defer). **Avoid:** Pattern 2 (CSS animation, sem esperar JS). **Warning:** lhci LCP >2,0 s, ou "element render delay" alto no trace.

### 2. `container-type:inline-size` em `.site` muda contexto de `position:fixed` e de `cqi`
**What:** containment de layout/estilo/inline-size faz `.site` ser o containing block de descendentes `position:fixed` e `cqi` só resolve dentro. **Avoid:** header (sticky), floating WhatsApp (sticky), main, footer **todos dentro de `.site`**; nada `position:fixed` crítico (skip link fica no `body` ou dentro de `.site` sem fixed). Texto do próprio `.site` usa `svw`-fallback.  **Warning:** header some/posiciona errado; clamp com `cqi` cai em `0`.

### 3. Páginas secundárias sem header/footer
`404`, `obrigado`, `politica-de-privacidade` hoje renderizam só `<main>`. D-15 diz "inherit header and footer via BaseLayout" — hoje o layout não os contém. **Avoid:** mover `SiteHeader`/`SiteFooter` para `BaseLayout` (nav âncora das seções deve apontar para `/#servicos` fora da home) e `.site` wrapper.

### 4. `overflow-clip-margin` ausente no Safari — descendentes cortados
Pattern 4.

### 5. IO não dispara em elemento recortado (foto)
Pattern 7. Também: `threshold:.12` em cards altos (bento `span 4×2` em mobile) pode nunca chegar a 12% — preferir `threshold:0` + `rootMargin` negativo para elementos grandes, e manter o timeout de segurança.

### 6. Estados escondidos aplicados cedo demais
`html.js-ready` é adicionado no `<head>` (antes do CSS pintar). Ocultar só sob `html.js-ready` **e** `@media (prefers-reduced-motion:no-preference)`; se o bundle falhar, o timeout (2,6 s) revela. Hoje `reveal.ts` revela todos os `[data-reveal]` aos 2,6 s — manter, estender aos novos `[data-r]`.

### 7. CLS por fonte e por mocks
`optimizedFallbacks:true` mitiga troca de Sora/Inter Tight. Mocks e captura precisam de `aspect-ratio`/`width,height` fixos; `min-height:320/240` do card destaque conforme UI-SPEC. Transform/opacity/filter/clip-path não geram CLS. Barras do menu `details` abrindo não deve empurrar conteúdo (painel `position:absolute`).

### 8. Tap targets em `<summary>` e links de footer/nav
`min-height:44px` com padding (UI-SPEC). `<summary>` com `list-style:none` e `::-webkit-details-marker{display:none}` (já existe). Chips `<label>` ≥44 px; input radio nativo visualmente oculto **sem `display:none`** (usar visually-hidden) para manter foco e teclado. `:has(input:focus-visible)` ou `input:focus-visible + label` para anel de foco.

### 9. Anchors e scroll-margin
`scroll-margin-top` usa `--nav-height` (a remover). Trocar por literal (68–84 px) nas âncoras novas (`servicos, projetos, processo, sobre, contato`), remover `#diferenciais/#faq`. Header muda de altura 84→68: o `scrolled` e o scroll-margin devem usar o menor valor + folga.

### 10. `pnpm test` sem testes
`package.json` → `node --test "src/scripts/*.test.mjs"`; ao remover `particles.pure.test.mjs`, o glob não casa nada e (conforme versão do Node) pode falhar o CI. **Avoid:** manter ao menos 1 teste (ex.: `nav-active.pure.test.mjs`/cálculo de `--p`) ou trocar o script por um runner de checagens (`scripts/verify-*.mjs`). Decidir no plano 1.

### 11. Cases: união discriminada com `image()` e `strictObject`
Astro 7 usa Zod 4 via `astro/zod`; `z.discriminatedUnion('rotulo', [A, B])` com `z.strictObject` funciona; `image()` só no ramo do projeto próprio. `getCases()` deve ordenar por `order` (hoje não ordena). Mocks de exemplo: componente escolhido por um campo `mock` enum (`agenda|clinica|pedidos`) no ramo `exemplo de escopo`, não por HTML no YAML. **[ASSUMED]** compat do discriminatedUnion com o loader `glob` — validar com `pnpm astro sync`.

### 12. Captura "do próprio site" é circular
O card destaque exibe a captura do site pronto, que por sua vez contém o card. **Avoid:** capturar uma rota/flag sem o card (ou aceitar o card pequeno dentro do print), a 1280 px, DPR 1, AVIF ~q60, largura de saída ≤1000 px; gerar com script versionado (`scripts/capture-site.mjs`) e commitar o asset; nova captura só quando o design mudar. Tamanho alvo <80 KB AVIF. O resultado do build com captura embutida no card não pode inflar `index.html`.

### 13. Contraste/AA nos tokens novos
Todos os pares da UI-SPEC são AA (muted ~7,8:1; faint ≥4,5:1). Verificar também: `#7FDCFF` em tag sobre card; ciano `.accent` `#00C8FF` sobre `#070A14` (alto); placeholder `#8F98A8`; texto ember `#FF6A3D` pequeno (legenda etapa 01 em `--text-xs`) sobre `#070A14` ≈ 6:1 [ASSUMED, medir com axe]. Lighthouse a11y cobre parte; rodar axe nos estados de erro.

### 14. SEO/Docs derivados da remoção do FAQ

## Security Domain

> `security_enforcement` não está `false`; aplica-se. A fase é de apresentação, mas mexe em markup de formulário e CSP-compat.

### Applicable ASVS Categories
| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | não | — |
| V3 Session Management | não | sem cookies (Vercel Analytics cookieless) |
| V4 Access Control | não | — |
| V5 Input Validation | parcial | Markup do form sem `action`/handler na 4.1; validação server-side só na Fase 5; `type`/`maxlength`/`autocomplete` corretos já agora |
| V6 Cryptography | não | — |
| V12/V14 Config (headers/CSP) | sim | Sem `style=`; sem origens de terceiros; sem `eval`/`new Function`; grão e fontes same-origin; sem `data:` desnecessário |

### Known Threat Patterns
| Pattern | STRIDE | Mitigação padrão |
|---------|--------|------------------|
| Injeção via `set:html`/innerHTML em conteúdo de collections | Tampering/XSS | Não usar `set:html`; ícones SVG como formas estruturadas (padrão da Fase 3); o split de palavras renderiza texto escapado |
| Quebra de CSP futura (`style-src-attr`) | DoS de estilo | Gate `style=`; CSSOM para valores dinâmicos |
| Links `target=_blank` | Tabnabbing | `rel="noopener noreferrer"` em WhatsApp/PageSpeed/Instagram |
| Dados pessoais em captura | Info disclosure | A captura é da própria home pública; nada de dados de form |
| Dependência nova (Playwright) | Supply chain | Checkpoint, `pnpm audit`, `onlyBuiltDependencies` sem postinstall |
| Chip/radio sem handler | — | Nenhum JS de form (D-11) |
