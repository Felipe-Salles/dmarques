# Phase 04.1: Redesign Aurora técnica - Context

**Gathered:** 2026-10-15
**Status:** Ready for planning

<domain>
## Phase Boundary

The live landing page (and the secondary pages through the shared layout) adopts the validated
"Aurora técnica" direction from sketch 001, variant A: new palette and tokens, Sora + Inter Tight
via the Fonts API, logo lockup, the sketch's section compositions (including a new Projetos bento),
"nós" voice with the single CTA "Pedir orçamento", and the "a luz acende" motion system —
without regressing Lighthouse ≥95, accessibility, or the static/CSP-safe architecture.

Visual direction, palette, typography, per-section composition, copy voice and motion thesis are
already locked by the sketch-findings skill and are NOT re-decided here. This context only resolves
the gaps between the current site and the sketch.

</domain>

<decisions>
## Implementation Decisions

### Page structure (sections outside the sketch)
- **D-01:** Final section order follows the sketch exactly:
  header → hero → serviços → **projetos (new)** → método → sobre → contato → footer.
- **D-02:** **FAQ section is removed.** Delete `FaqSection.astro` and the `faq` content collection
  (`src/content/faq/*`, its schema in `src/content.config.ts`, any export in `src/content/index.ts`).
  Consequence: **SEO-07 (FAQPage JSON-LD) and CONTENT-04 must be dropped/rewritten** in
  REQUIREMENTS.md and the Phase 6 roadmap entry (Google only accepts FAQPage for visible FAQ
  content). The planner must include a task updating REQUIREMENTS.md + ROADMAP.md Phase 6 accordingly.
- **D-03:** Claims previously published only in the FAQ ("Nada é cobrado antes de você aprovar o
  plano", "Escopo e prazo saem fechados na proposta, depois do diagnóstico", "Respondemos no mesmo
  dia útil") remain the allowed claims; they now live as content of the Contato "o que acontece
  depois" block and Método step 01. No new claims (price, deadlines, guarantees).
- **D-04:** **Diferenciais are absorbed into Sobre** as the 2-column hairline list from the sketch.
  The `differentiators` collection stays and is rendered inside `AboutSection`;
  `DifferentiatorsSection.astro` (the separate light section) is removed.
- **D-05:** **CtaFinal is removed.** Contato (with the inverted aurora) closes the page.

### Project proof (new Projetos bento)
- **D-06:** The featured card ("No ar · projeto próprio") shows a **real full-page capture of the
  redesigned dmarques site**, scrolling inside the browser frame only while visible (IO toggles
  `animation-play-state`, pauses on hover, static under reduced-motion). Generated at the end of the
  phase (Playwright screenshot of the finished site → optimized via `astro:assets`, AVIF/WebP).
  Until the capture exists, the sketch's CSS mock stands in. The capture replaces the outdated
  `dmarques-cover.webp` (which shows the old violet design) and its `coverAlt` must be updated.
- **D-07:** "Exemplo de escopo" cards live in the **`cases` collection**: the `rotulo` enum changes
  from `'projeto próprio' | 'demo'` to `'projeto próprio' | 'exemplo de escopo'` (update CONTENT-03
  wording accordingly). Each example entry carries title/description/tipo; the schema must allow
  example entries without problema/solução/resultado and without a cover image (planner decides the
  schema shape, e.g. discriminated union on `rotulo`). The visual mock for each example (agenda,
  site de clínica, pedidos processados) is an HTML/CSS component with realistic content — no images,
  no invented metrics.
- **D-08:** **No case detail page in this phase.** The featured card shows results in lay language
  ("abre em ~1,5 s no celular", "nota 95+ no Google PageSpeed", "zero cookies de rastreamento");
  the hero proof line links to PageSpeed. Technical terms (LCP/TBT/CLS/CSP) don't appear on the page.

### Contact form (4.1 vs Phase 5 split)
- **D-09:** Keep the **5 FORM-01 fields** (Nome, WhatsApp, E-mail, Tipo de projeto, Mensagem) with the
  "Preencha WhatsApp ou e-mail" note — the sketch's 4-field form is NOT adopted. Labels visible,
  "(opcional)" explicit where applicable, inputs ≥48px.
- **D-10:** Tipo de projeto becomes **optional chips**: native radio inputs styled as chips
  (work without JS and with keyboard), nothing preselected, options from `PROJECT_TYPES` in
  `src/content/project-types.ts` (allow-list unchanged). The `required` on the current `<select>` is
  dropped. "Click again to deselect" is a JS enhancement left to Phase 5.
- **D-11:** 4.1 delivers **markup + glass styling + all visual states ready in CSS** (error with
  `aria-invalid`/`aria-describedby` hooks, sending with spinner, success with drawn ✓ and hidden form,
  sr-only always-rendered live region element). Phase 5 wires `action`/`method`, validation, WhatsApp
  mask, live-region announcements, fetch and state switching. No form JS in 4.1.

### Effects, navigation and secondary pages
- **D-12:** **Cursor glow is removed** together with the particle canvas: delete `glow.ts`,
  `particles.ts`, `particles.pure.ts`, `particles.pure.test.mjs`, the glow element in
  `BaseLayout.astro`, and the static `.hero-glow`. This supersedes Phase 4 D-01..D-09 and the
  ANIM-03/04/05 implementations (planner updates REQUIREMENTS.md to reflect the aurora replacing them).
  The aurora is the only light source.
- **D-13:** The single bundled module script (Phase 4 D-10) and the tiny inline `.js-ready` toggle in
  `<head>` (Phase 4 D-11) stay as the architecture; the new motion system (word reveal, per-section
  reveals, scroll-driven method line, clip-path photo, browser-frame scroll, header glass, active nav)
  is built on top of `reveal.ts`/`effects.ts`.
- **D-14:** Mobile nav **keeps native `<details>`/`<summary>`** (Phase 3 D-04, zero JS, no focus trap)
  with the sketch's visual (glass panel, 48px links, 44×44 trigger). A tiny optional JS enhancement may
  close the menu when an anchor link is clicked. "Pedir orçamento" stays outside the menu (Phase 3 D-05).
- **D-15:** `/obrigado`, `/404`, `/politica-de-privacidade` inherit the new tokens, fonts, header and
  footer via `BaseLayout`, plus a simple coherent composition (small static aurora at the top). None of
  the home page's elaborate motion.

### Claude's Discretion

  claims), and updates to the existing YAML entries to fit.
- Cases schema shape for D-07 (discriminated union vs optional fields).
- How/when the Playwright capture is generated (script in repo vs one-off) and capture dimensions.
- Breakpoints, timings, easing values and stagger beyond what the sketch specifies.
- Whether `HeroBleed.astro` is rewritten in place or replaced by a new hero component; whether
  `hero-render-placeholder.webp` is deleted (the centered aurora hero no longer uses it).

</decisions>

### Established Patterns
- Inline-style gate: no `style=""` attributes (CSP `style-src-attr`); per-element values (e.g. `--i`, `--d` stagger) must come from classes or be set via JS/CSSOM, not inline attributes.
- Astro `security.csp` auto-hashes scripts/styles; no third-party origins (fonts self-hosted).
- `.js-ready` gate on `<html>`: everything visible without JS.

### Integration Points
- `src/pages/index.astro`: section composition (remove Faq/Differentiators/CtaFinal, add Projetos).
- `src/layouts/BaseLayout.astro`: fonts, glow element removal, script bundle, secondary pages.
- `src/styles/tokens.css` / `base.css`: palette + type migration (no `#6C4CFF` left).
- `astro.config.mjs` `fonts`: Outfit/DM Sans → Sora + Inter Tight (+ JetBrains Mono for data, if used).
