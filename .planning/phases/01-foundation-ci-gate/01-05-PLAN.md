<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local working tree → public GitHub repository | Everything pushed is permanently world-readable |
| OAuth token scopes → repository write access | Broadening scope broadens blast radius |
| GitHub account → repository administration | Account compromise means repository compromise |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | First push to a public repository | mitigate | Task 3 asserts `git ls-files` contains nothing under `node_modules`, `dist`, `.vercel`, `.astro`, `.lighthouseci`; no secret value exists anywhere in the tree (only the `astro:env` key NAME is declared, per plan 01) |
| T-05-02 | Elevation of Privilege | `gh` token scope broadened to `workflow` | accept | The `workflow` scope is the minimum required to push `.github/workflows/*` (Pitfall 8); it is granted interactively by Felipe on his own account and is narrower than `admin:org` or `delete_repo` |
| T-05-03 | Tampering | Unreviewed or force-pushed code on `main` | mitigate | Deferred by one plan on purpose: branch protection is applied in plan 07 once the exact required-status-check contexts are known. The window between push and protection is a single-operator window with no external contributors |
| T-05-04 | Spoofing | GitHub account takeover | mitigate | 2FA on the GitHub account is verified as part of the INFRA-10 hardening checklist recorded in plan 08's run file |
| T-05-05 | Repudiation | Irreversible actions taken without consent | mitigate | Task 1 is a blocking decision checkpoint covering repository creation, public visibility, branch rename and first push (D-03); Task 2 is a blocking human action |

Residual: none rated High. T-05-03 is the only open window and closes in plan 07.
</threat_model>
