# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1 (Foundation & CI Gate). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Language:** pt-BR only. All visible copy in this contract is pt-BR.

---

## Phase 1 Scope

This is a **narrow infrastructure phase**. It ships exactly two user-facing surfaces:

1. **`src/styles/tokens.css`** — one CSS custom-properties file, the single source of truth every later component consumes (INFRA-04). The token contract below is complete and correctly named **now** so Phase 3 can convert the design's inline styles against it and add zero new tokens for anything already visible in `arquivos de design/Dmarques Landing.dc.html`.
2. **`BaseLayout.astro` + `src/pages/index.astro`** — a minimal placeholder page: `<main>` with one `<h1>` and the Core Value tagline, dark background, self-hosted Outfit/DM Sans, tokens applied. It exists only to deploy and score Lighthouse mobile ≥95 (D-08). No header, no nav, no footer, no "coming soon" copy.

**Explicitly OUT for Phase 1** (do not design, do not block): the 9 landing sections, component inventory, section layouts, cursor glow, particle canvas, reveal-on-scroll, `dmFloat` / `dmPulse` keyframes. Those are Phase 3 (sections + CSP-safe refactor + a11y) and Phase 4 (effects). The token file must not block them — see [Downstream Handoff](#downstream-handoff).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Astro SSG; no shadcn, no UI framework — PERF-03 hard constraint: no UI framework, no animation library) |
| Preset | not applicable |
| Component library | none — plain `.astro` components + token-based CSS |
| Icon library | none in Phase 1 (design uses hand-authored inline `<svg>`; introduced Phase 3) |
| Font | **Outfit** (headings/display) + **DM Sans** (body), self-hosted via the Astro Fonts API with `fontProviders.fontsource()`, `display: 'swap'`, `optimizedFallbacks: true` |
| Styling approach | Global external stylesheets only (`build.inlineStylesheets: 'never'`, INFRA-05). `tokens.css` = tokens; a sibling `base.css` = reset + element base rules. Both imported once in `BaseLayout.astro`. |
| Token file naming | Category prefix + semantic role for color (`--color-bg`, `--color-accent`, never `--color-purple-500`); category prefix + numeric step for scales (`--space-4`, `--text-lg`, `--radius-md`). Flat single `:root` block, no nesting, no `@layer` in Phase 1. |

## Spacing Scale

4px base grid. Every value below is a multiple of 4. Derived from `arquivos de design/Dmarques Landing.dc.html` (`clamp(80px,9vw,130px)` section padding, `clamp(20px,4vw,56px)` gutters, 14/18/20/24/26px internal gaps) and the RESEARCH.md skeleton.

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Hairline gaps, icon-to-label nudge |
| `--space-2` | 8px | Compact stack gaps (label → field) |
| `--space-3` | 12px | Icon gaps, chip padding |
| `--space-4` | 16px | Default element spacing, input padding-block |
| `--space-5` | 20px | Card inner padding (small) |
| `--space-6` | 24px | Card inner padding, headline → body gap |
| `--space-8` | 32px | Group gaps, hero content stack |
| `--space-10` | 40px | Column gaps |
| `--space-12` | 48px | Sub-section breaks |
| `--space-16` | 64px | Major block breaks |
| `--space-20` | 80px | Section padding (min rung) |
| `--space-24` | 96px | Section padding (large viewports) |
| `--space-section` | `clamp(5rem, 9vw, 8.125rem)` | Vertical section rhythm (Phase 3) — fluid, resolves 80px→130px |
| `--space-gutter` | `clamp(1.25rem, 4vw, 3.5rem)` | Horizontal page inset (Phase 3) — fluid, resolves 20px→56px |

**Exceptions:** none in Phase 1 (the placeholder page has no interactive elements). Downstream note: Phase 3 CTAs and nav links must have a ≥44px hit target.

**Phase 1 page uses:** `--space-gutter` (page inset), `--space-16` (page padding-block), `--space-6` (`<h1>` → tagline gap). Nothing else.

## Typography

### Rendered by the Phase 1 placeholder page

Exactly **2 roles, 2 weights, 2 sizes** are exercised this phase.

| Role | Element | Family | Size | Weight | Line height | Tracking | Color |
|------|---------|--------|------|--------|-------------|----------|-------|
| Display | `<h1>` | `var(--font-heading)` (Outfit) | `clamp(2rem, 1.4rem + 3vw, 3rem)` (32→48px) | `var(--font-weight-bold)` (700) | `var(--leading-tight)` (1.1) | `var(--tracking-tight)` (-0.03em) | `var(--color-text-strong)` |
| Body | tagline `<p>` | `var(--font-text)` (DM Sans) | `var(--text-lg)` (18px) | `var(--font-weight-regular)` (400) | `var(--leading-body)` (1.6) | `var(--tracking-normal)` (0) | `var(--color-text)` |

Line-height values intentionally diverge from the generic 1.5/1.2 template defaults: they come from the locked design (`1.02`–`1.08` headings, `1.65` body), tightened slightly to `1.1` / `1.6` for the placeholder.

| `--text-sm` | 0.875rem (14px) | Field labels, footer links, meta |
| `--text-base` | 1rem (16px) | Default body |
| `--text-lg` | 1.125rem (18px) | Lead paragraph, FAQ text |
| `--text-xl` | 1.375rem (22px) | Card `<h3>` |
| `--text-2xl` | 1.75rem (28px) | Small `<h2>` |
| `--text-3xl` | 2.25rem (36px) | Section `<h2>` (min rung) |

| `--text-5xl` | 3.75rem (60px) | Hero `<h1>` (large viewports) |

Section and hero headings in Phase 3 wrap these in `clamp()` for fluid scaling (design pattern: `font:700 clamp(30px,3.6vw,50px)`).

### Weight tokens

| Token | Value | Design usage |
|-------|-------|--------------|
| `--font-weight-regular` | 400 | Body copy (DM Sans), logo descriptor |
| `--font-weight-medium` | 500 | Nav links, eyebrow labels, WhatsApp inline link (DM Sans) |
| `--font-weight-semibold` | 600 | Buttons/CTAs, card `<h3>` (Outfit + DM Sans) |
| `--font-weight-bold` | 700 | `<h1>`, `<h2>`, logo wordmark, step numbers (Outfit) |

**Font-loading recommendation (Claude's discretion — INFRA-03 / PERF-04):** load **Outfit `[400, 500, 600, 700]`** and **DM Sans `[400, 500]`** — the exact set the design renders. This is narrower than the "Outfit 300–800" phrasing in CONTEXT.md (which described the design file's Google Fonts `<link>`, now deleted). Weights 300 and 800 are unused by any current design element; add them only if a Phase 3 design refinement calls for them. `preload` exactly two files: **Outfit 700** (LCP `<h1>`) + **DM Sans 400** (body). `--font-display` / `--font-body` are injected by the Fonts API `cssVariable` option (family + metrics-adjusted fallback + `system-ui, sans-serif`); `tokens.css` must **not** redefine them — it composes `--font-heading: var(--font-display)` and `--font-text: var(--font-body)` only.

## Color

60 / 30 / 10 split for the finished site. On the Phase 1 placeholder page the dominant surface is effectively 100% — there are no cards, nav, or accent elements.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--color-bg` | `#0A0A12` | Page background, all dark sections. **Phase 1 page background.** |
| Secondary (30%) | `--color-surface` | `rgba(255,255,255,0.045)` | Cards, glass panels, nav pill (Phase 3). **Not exercised in Phase 1.** |
| Accent (10%) | `--color-accent` | `#6C4CFF` | See reserved-for list below. **Not exercised in Phase 1 (zero accent on the placeholder — deliberate).** |
| Semantic — error | (not defined Phase 1) | — | Form error states are Phase 5; token added then. No destructive actions exist in this project. |

**Accent (`--color-accent` `#6C4CFF`) is reserved for, downstream only:**
- Primary CTA fill and its hover (`--color-accent-hover` `#7E62FF`)
- Text links (`<a>`) and their hover (`--color-accent-light` `#9A85FF`)
- Eyebrow / overline labels ("Sites · Sistemas · Automação", "O que fazemos")
- A single emphasised phrase inside a heading (design pattern: `<span style="color:#6C4CFF">funcionar melhor</span>`)
- Icon strokes, 1px rule marks, step-marker dots
- `:focus-visible` ring (`--focus-ring`)
- Accent-tinted card fills/borders and the ambient glow gradients

Never "all interactive elements", never applied to body text, never used as a large background fill except the low-alpha radial glows.

### Document structure (`BaseLayout.astro` + `index.astro`)

```
<!doctype html>

  <head>

    <Font cssVariable="--font-body"    preload={[{ weight: 400, style: 'normal' }]} />

  <body>
    <main>

    </main>
    <script>/* @vercel/analytics inject() — D-05/D-06 */</script>

```

- Exactly **one `<h1>`** (A11Y-02). No `<header>`, `<nav>`, `<footer>` (D-08, deferred to Phase 3).
- `<main>` MAY carry `id="conteudo"` to pre-wire the Phase 3 skip link (A11Y-01); optional, no skip link ships this phase.
- No `<meta name="description">`, no canonical, no OG, no favicon — all Phase 6.
- No `<meta http-equiv="content-security-policy">` — CSP is Phase 7; do not enable `security.csp` in `astro.config.mjs` now.

| Element | Rule |
|---------|------|
| `<body>` | `background: var(--color-bg); color: var(--color-text); font-family: var(--font-text); margin: 0; -webkit-font-smoothing: antialiased;` |
| `<main>` | `min-height: 100svh; display: grid; place-items: center; padding: var(--space-16) var(--space-gutter); text-align: center;` |
| content column | wrapper (or `<main>` itself) `max-width: 42rem; display: flex; flex-direction: column; gap: var(--space-6);` |

| tagline `<p>` | `font-family: var(--font-text); font-weight: var(--font-weight-regular); font-size: var(--text-lg); line-height: var(--leading-body); color: var(--color-text); max-width: 34rem; margin: 0 auto; text-wrap: pretty;` |

### Light / dark behaviour

The Phase 1 page is **dark only** — `--color-bg` `#0A0A12` end to end. `color-scheme: dark` on `:root` so native UI (scrollbars, future form controls) renders dark. The `--color-light-*` tokens are defined but unused; Phase 3 decides whether light sections re-map `--color-bg` / `--color-text` inside a `.section--light` scope or consume `--color-light-*` directly.

### Reduced-motion baseline

**There is no motion on this page.** No `@keyframes`, no `transition`, no `animation`, no `scroll-behavior: smooth` (the design file's `html{scroll-behavior:smooth}` is deliberately not carried over — nothing scrolls). `prefers-reduced-motion` is therefore satisfied trivially with no media query required. Motion tokens (`--dur-*`, `--ease-*`) exist in `tokens.css` for Phase 3 hover/focus transitions (≤300ms, transform/opacity/box-shadow/border-color only — ANIM-07) but are applied by nothing in Phase 1.

## Accessibility & Interaction Contract

| Concern | Phase 1 state |
|---------|---------------|
| Language | `<html lang="pt-BR">` |
| Landmarks / headings | `<main>` present; exactly one `<h1>`; no heading-level skips (only `<h1>`) |
| Keyboard | Zero focusable elements (no links, no buttons, no form). Document is trivially keyboard-navigable. No focus trap possible. |
| `:focus-visible` | No interactive elements → no focus styles needed this phase. `--focus-ring` token reserved for Phase 3 (A11Y-03: ≥3:1 contrast on both dark and light — the 3px `#6C4CFF` ring meets this). |
| Contrast — `<h1>` | `--color-text-strong` (`rgba(255,255,255,0.92)`) on `#0A0A12` ≈ **16.6:1** — exceeds WCAG AAA (7:1). PASS. |
| Contrast — tagline | `--color-text` (`rgba(255,255,255,0.82)`) on `#0A0A12` ≈ **12:1** — exceeds WCAG AAA. PASS. |
| Low-opacity text tokens | `--color-text-faint` (0.45) computes to ≈ 4.5:1 on `#0A0A12` — borderline for normal body text. **Provisional** (RESEARCH Pitfall 9): not used on the Phase 1 page; A11Y-06 (Phase 3, with design sign-off) raises the low rungs. Same caveat for `--color-light-text-faint` on light sections. Do not use faint tokens for body text. |
| Reduced motion | Nothing to gate (see baseline above). |
| Images | None on this page. Founder portrait alt text + decorative `aria-hidden` on render/canvas/glow are Phase 3 (A11Y-05). |
| Target size | No targets this phase. |

Expected Lighthouse Accessibility on the placeholder page: **100**.
