<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request → protected production branch | The merge gate is the last barrier before code goes live |
| branch protection configuration → GitHub enforcement | A mistyped context string silently disables a required check |
| deliberate-failure experiment → repository history | Broken code and a denylisted dependency briefly exist on a branch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | Unreviewed or force-pushed code on `main` | mitigate | Branch protection with `strict` required checks, `allow_force_pushes: false`, `allow_deletions: false`, `required_linear_history: true`, PR required; verified by an empirical rejected direct push, not just an API readback |
| T-07-02 | Spoofing | A required status check that never actually runs | mitigate | Context strings are copied verbatim from what GitHub reported on a live PR (Open Question 4) rather than guessed; Task 2 asserts every configured context matches an observed check name |
| T-07-03 | Tampering | Denylisted dependency reaching `main` during the experiment | mitigate | Every deliberate failure is introduced on a throwaway branch, reverted before the next one, and asserted absent from the final diff; the branch is deleted after merge |
| T-07-04 | Spoofing | Lighthouse scoring a login page instead of the site | mitigate | Task 1 Phase D reads the actual category scores and flags the 92-94 Best-Practices signature that indicates a misdirected run (Pitfall 3 / Pitfall 6) |
| T-07-05 | Elevation of Privilege | `enforce_admins: false` lets an admin bypass the gate | accept | Deliberate for a solo operator so an emergency fix is possible (RESEARCH anti-pattern L469); the operator and the reviewer are the same person, so admin enforcement would only add friction. Revisit if a second contributor joins |
| T-07-06 | Information Disclosure | Production deployment reachable | mitigate | The real domain stays unattached until after Phase 7 (D-09) and the generated production URL sits behind Deployment Protection |

Residual: T-07-05 accepted, rated Low for a single-operator repository. None rated High.
</threat_model>
