<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fork PR author → CI runner | Untrusted code executes in a workflow that has access to repository configuration |
| GitHub Actions secrets → workflow logs | `VERCEL_AUTOMATION_BYPASS_SECRET` crosses into an action's environment |
| third-party GitHub Action → repository | Actions run with the workflow's token and permissions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | `VERCEL_AUTOMATION_BYPASS_SECRET` in `lighthouse.yml` | mitigate | Trigger is `deployment_status`, never `pull_request_target`, so a fork PR cannot read repository secrets; the secret is only interpolated into the `LHCI_EXTRA_HEADERS` env value and never echoed in a `run:` step |
| T-04-02 | Elevation of Privilege | Workflow `GITHUB_TOKEN` scope | mitigate | Top-level `permissions: contents: read`; `statuses: write` granted only in `lighthouse.yml` where posting the check requires it |
| T-04-03 | Tampering | Third-party actions in the supply chain | mitigate | Every action pinned to an explicit major tag whose existence is verified via the GitHub API before writing; `actions/checkout`, `pnpm/action-setup`, `actions/setup-node`, `actions/dependency-review-action`, `treosh/lighthouse-ci-action` are all widely used first-party or well-known publishers |
| T-04-04 | Tampering | Dependency tree drift between local and CI | mitigate | `pnpm install --frozen-lockfile` fails the job if `pnpm-lock.yaml` does not match `package.json` |
| T-04-05 | Tampering | Malicious dependency introduced in a PR | mitigate | `dependency-review-action` blocks the PR diff at `fail-on-severity: high`; `pnpm audit --audit-level=high` covers the resolved tree |
| T-04-06 | Spoofing | Lighthouse scoring the SSO login page instead of the site | mitigate | The `x-vercel-protection-bypass` header is sent on every Lighthouse request (Pitfall 3); plan 07 verifies the run reports real page metrics, not a login screen |
| T-04-07 | Denial of Service | Flaky `deployment_status` association with the PR head SHA | accept | Assumption A7; plan 07 empirically confirms the check appears on a live PR, and RESEARCH documents the local-static-server fallback if it does not |

Residual: none rated High.
</threat_model>
