Accept an optional `--ci` flag (non-interactive, machine-parseable output) and read `STATIC_DIR`, `PREVIEW_URL`, `VERCEL_AUTOMATION_BYPASS_SECRET` from the environment, with `STATIC_DIR` defaulting to the value resolved in `01-02-SUMMARY.md`.

Implement exactly these seven checks, each printing a single line beginning `PASS:`, `FAIL:` or `SKIP:` followed by detail, and each incrementing a failure counter on `FAIL`:

1. `pnpm audit --audit-level=high` — non-zero exit → FAIL. The `high` threshold matches `dependency-review-action`'s `fail-on-severity` (Pitfall 7); lower-severity advisories are recorded as findings in the run file, never silently ignored.
2. `grep -rn 'style="' src/` — any hit → FAIL. Phase 1 has none; this guards the Phase 3 inline-style regression early.
3. Inline-surface count in the built HTML: count `<style` occurrences and non-hashed inline `<script>` blocks across `"$STATIC_DIR"`/**/*.html and report the number. Phase 1 baseline is 0 inline `<style>`; report, and FAIL if any inline `<style>` block is present.
4. Secret scan: `grep -rIE 'RESEND_API_KEY|re_[A-Za-z0-9]{20,}' "$STATIC_DIR" .vercel/output` — any hit → FAIL. Use exactly this tight regex; a bare `re_` matches minified identifiers and produces false failures (Pitfall 4).
5. Function count: `find .vercel/output/functions -maxdepth 1 -name '*.func' 2>/dev/null | wc -l` → FAIL only when the count is greater than 1. Assert `<= 1`, NEVER `== 1` — Phase 1's correct count is 0 and Phase 5 makes it exactly 1 (Pitfall 1).
6. `curl -sI -H "x-vercel-protection-bypass: $VERCEL_AUTOMATION_BYPASS_SECRET" "$PREVIEW_URL"` — print the response headers and always PASS in Phase 1 (this records the baseline; the header assertions become meaningful in Phase 7). SKIP with a printed reason if `PREVIEW_URL` is unset. Never echo the bypass secret value itself.
7. Lighthouse gate: if `PREVIEW_URL` is set, run `pnpm exec lhci autorun --collect.url="$PREVIEW_URL" --config=./lighthouserc.json` (or read an already-uploaded assertion result) — non-zero → FAIL. SKIP with a printed reason if no URL is available.

Finish by printing a summary line with the PASS/FAIL/SKIP counts and `exit 0` if and only if the failure counter is 0 (SKIPs are allowed). Never print the value of any secret.

`chmod +x scripts/security-check.sh`. Comment-free apart from the shebang (D-04).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → build output | The scripts are the only automated inspector of what ships |
| environment variables → script output | `VERCEL_AUTOMATION_BYPASS_SECRET` passes through the script and must never reach logs |
| PR author → dependency tree | A PR can add any package; the denylist and audit are the gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | `security-check.sh` check 6 | mitigate | The bypass secret is passed as a `curl` header from an environment variable and never echoed; the acceptance criteria assert no secret-shaped string appears in stdout |
| T-03-02 | Information Disclosure | Built assets | mitigate | Check 4 greps `$STATIC_DIR` and `.vercel/output` with the tight `re_[A-Za-z0-9]{20,}` regex plus literal env-var names, avoiding both false negatives and Pitfall-4 false positives |
| T-03-03 | Tampering | Dependency tree | mitigate | `js-weight-check.sh` denylist blocks UI-framework / animation-library creep; `pnpm audit --audit-level=high` blocks known-vulnerable packages |
| T-03-04 | Elevation of Privilege | Vercel function surface | mitigate | Check 5 asserts `<= 1` function so an accidental extra dynamic route is caught before it deploys |
| T-03-05 | Repudiation | Security review record | mitigate | The gabarito mandates a findings table with severity, owner (Felipe Salles) and target date, and the hard "no open High" rule; every phase produces a dated run file |
| T-03-06 | Tampering | Gate bypass via drift | mitigate | One script, invoked identically by humans and CI (D-11), so a locally-passing check cannot diverge from the merge gate |
| T-03-07 | Denial of Service | Unfixable low-severity advisory blocking every PR | accept | Threshold set at `high` (Pitfall 7); lower-severity advisories are logged as Low/Med findings with an owner and target date rather than blocking. Threshold to be confirmed with Felipe in plan 05 |

Residual: none rated High.
</threat_model>
