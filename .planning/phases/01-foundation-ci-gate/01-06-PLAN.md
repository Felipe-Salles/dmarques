Pro ($20/mo, Owner or Billing role required) gives a named-dollar cap, configurable alerts, and a pause-production action — which is what "an attack degrades gracefully (form off) instead of an unbounded bill" in the SEC-08 statement actually describes. This matters because SEC-08 already accepts the absence of edge WAF/DDoS protection in v1 and lists the spend cap as one of the compensating controls holding that acceptance together.

Whichever option is chosen, the SEC-08 wording in `.planning/ROADMAP.md` must end up accurately describing the real mechanism. CONTEXT already lists "the exact spend-cap amount" as needing Felipe's confirmation.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → preview deployment | An unprotected preview exposes work in progress to anyone and to search engines |
| Vercel dashboard → project runtime configuration | Settings here are not reconstructible from git |
| bypass secret → CI runner and shell history | The secret defeats Deployment Protection for whoever holds it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Information Disclosure | Preview deployments | mitigate | Deployment Protection set to Vercel Authentication on previews and production; the real domain stays unattached until after Phase 7 (D-09); Task 3 empirically proves an unauthenticated request is refused |
| T-06-02 | Information Disclosure | `VERCEL_AUTOMATION_BYPASS_SECRET` | mitigate | Copied by Felipe directly from the Vercel dashboard into `gh secret set` at an interactive prompt, never pasted into chat, never committed, never echoed by any workflow step; consumed only by the `deployment_status`-triggered job that fork PRs cannot reach |
| T-06-03 | Spoofing | GitHub or Vercel account takeover | mitigate | 2FA required on both accounts (INFRA-10, checklist item 1) |
| T-06-04 | Denial of Service / cost attack | Unbounded Vercel usage under a flood | mitigate | Task 1 decides and Task 2 applies the spend ceiling; the site is 100% static so GET floods are absorbed at the CDN edge; the residual gap (no edge WAF/DDoS until Milestone 2) is the accepted SEC-08 statement, whose spend-cap bullet is corrected here to describe the real mechanism |
| T-06-05 | Information Disclosure | Environment variable scoping | mitigate | No secret values are added in this phase; `RESEND_API_KEY` arrives in Phase 5 scoped to Production + Preview and marked Sensitive, never "All Environments" |
| T-06-06 | Repudiation | Dashboard-only state lost to time | mitigate | Every configured setting is recorded in `.planning/security/runs/phase-01.md` by plan 08 — the record of truth for state git cannot hold |

Residual: none rated High for Phase 1. The SEC-08 edge-protection gap remains knowingly accepted and is closed by Milestone 2.
