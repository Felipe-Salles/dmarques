    **`src/scripts/reveal.ts` — `export function initReveal(): void`**

    · Consulta `document.querySelectorAll('[data-reveal]')` uma vez.
    · Guard de suporte: se `!('IntersectionObserver' in window)`, adiciona
      `is-revealed` em todos e retorna. É o caminho degradado, não um extra.
    · Um único `IntersectionObserver` para todos os elementos, com opções exatamente
      `{ rootMargin: '0px 0px -8% 0px', threshold: 0.08 }`. Esses dois valores estão
      travados pelo critério de sucesso 1 do ROADMAP — não parametrizar, não ajustar.
    · No callback, para cada entry com `isIntersecting`: `classList.add('is-revealed')`
      e `io.unobserve(entry.target)` imediatamente, para que nunca dispare duas vezes.
    · Fallback: um `setTimeout` de exatamente `2600` ms, registrado no momento da
      inicialização, que adiciona `is-revealed` em todos os elementos e chama
      `io.disconnect()`.
    · PROIBIDO: escrever `element.style.opacity` ou `element.style.transform` daqui. O
      `base.css` já é dono da transição (`--dur-reveal` 0.7s, `--ease-out`). Este módulo
      só alterna classe. Esse é o padrão do DC-editor que o UI-SPEC §1 proíbe copiar.
    · NÃO checar `prefers-reduced-motion` aqui. O `base.css` envolve o estado oculto em
      `@media (prefers-reduced-motion: no-preference)`, então sob reduced-motion a troca
      de classe já é visualmente um no-op. Um branch em JS seria trabalho duplicado.
    · Tipagem strict: `querySelectorAll<HTMLElement>('[data-reveal]')` para que
      `classList` tipifique sem cast.

    **`src/scripts/glow.ts` — `export function initGlow(): void`**

    · Gate duplo, nesta ordem, com retorno antecipado:
      `window.matchMedia('(pointer: fine)').matches` E
      `window.matchMedia('(prefers-reduced-motion: no-preference)').matches`. Se
      qualquer um for falso, retorna ANTES de tocar no DOM e sem registrar listener
      nenhum (D-05: sob reduced-motion o glow não existe, nem estacionado).
    · `document.querySelector<HTMLElement>('.cursor-glow')`; se for `null`, retorna. O
      elemento é renderizado pelo `BaseLayout.astro` (Task 2) — NÃO criar via
      `document.createElement`: um elemento criado em runtime não recebe o atributo de
      escopo `data-astro-cid-*` e o `<style>` escopado do layout não se aplicaria a ele.
    · Um único listener: `window.addEventListener('pointermove', handler, { passive: true })`.
    · Throttle por rAF com flag de single-flight: uma variável `pending` booleana; se já
      estiver `true`, o handler retorna imediatamente; senão marca `true`, agenda um
      `requestAnimationFrame` que zera `pending` e escreve
      `glow.style.transform = 'translate3d(' + x + 'px, ' + y + 'px, 0)'` usando
      `event.clientX`/`event.clientY` capturados no handler (não ler o evento dentro do
      rAF via referência ao objeto de evento reciclado — copiar os dois números para
      variáveis antes de agendar).
    · A escrita de `style.transform` em runtime é a ÚNICA escrita de estilo inline
      sancionada nesta fase (UI-SPEC §2; a verificação 2 do `security-check.sh` só grepa
      o literal `style="` em arquivos-fonte, então isto não a aciona).
    · Nenhum outro efeito: sem `mouseenter`/`mouseleave`, sem timers, sem resize.

    Rodar `pnpm lint` e `pnpm check` ao final. Ainda não há wiring — os módulos não são
    importados por ninguém neste ponto, o que é esperado.
