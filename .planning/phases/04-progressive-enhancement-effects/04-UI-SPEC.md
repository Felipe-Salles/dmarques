# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note (read before applying the standard dimensions below)

Phase 4 adds **zero new pages, zero new components, zero new copy, and zero
new color/typography/spacing tokens**. It is a pure progressive-enhancement
JS layer (`src/scripts/*.ts` + two `<script>` tags in `BaseLayout.astro`)
that attaches behavior to markup and CSS Phase 3 already shipped in full
(`[data-reveal]` attributes, `.hero-canvas`/`.hero-glow` elements, the
`.js-ready`-gated reveal rules in `base.css`). All visual parameters for the
new motion (cursor glow, particle canvas) are **already locked verbatim** by
`04-CONTEXT.md` (D-01 through D-11), lifted directly from the design source
`arquivos de design/Dmarques Landing.dc.html`.

Consequently the standard template sections below (Typography, most of
Spacing, Copywriting) are marked **unaffected / no new decision** rather than
populated with invented values — inventing new type sizes or copy for a
phase that introduces neither would violate the "don't re-litigate locked
decisions" rule. The section that actually carries this phase's design
contract is **Motion & Interaction Contract**, added after Copywriting below.

## Color

**No new color tokens.** This phase reuses `--color-accent` (`#6C4CFF`, RGB `108,76,255`) exclusively — the same token already driving the existing static `.hero-glow` and the accent CTA states shipped in Phase 3.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` `#0A0A12` | Page background (unaffected, existing) |
| Secondary (30%) | `--color-surface` / `--color-light-bg` | Cards, nav, light sections (unaffected, existing) |
| Accent (10%) | `--color-accent` `#6C4CFF` (decomposed `rgb(108,76,255)` for canvas/gradient math) | See explicit reserved-for list below |
| Destructive | not applicable | No destructive action exists in this phase's scope |

**Accent reserved for (this phase's only two NEW accent usages — do not extend accent to anything else):**
1. **Cursor-glow radial gradient** — all three gradient stops are `rgba(108, 76, 255, α)` at α = `.28` (0%), `.10` (38%), `0` (68%), i.e. the accent color at 0% and 38% and fully transparent at 68%. `mix-blend-mode: screen`, unconditional (D-04) — no per-section blend override, including over light sections.
2. **Particle canvas** — every 4th point's fill (`i % 4 === 0`) uses `rgba(108, 76, 255, .75)`; all other points use white at low opacity (`rgba(255, 255, 255, .30)` — not an accent use, listed here only to be explicit that it is the *only* other fill color in the canvas); connection lines between points closer than 108px use `rgba(108, 76, 255, α)` where α scales `0.16 × (1 − distance/108)`.

No new interactive element (button, link, focus state) gets accent treatment in this phase — both usages above are `aria-hidden="true"` decorative layers.

**Token-authoring instruction (ties this contract back to INFRA-04):** the accent RGB triplet must be read from `--color-accent` via `getComputedStyle(document.documentElement)` inside the particle/glow script and decomposed with the existing hex→rgb parsing approach the design source already uses (kept as a pure string-parsing function, never `eval`) — **do not hardcode `#6C4CFF` or `108,76,255` a second time** in the TypeScript source. This mirrors the CONTEXT.md code_context note ("`--color-accent` token already defined in tokens.css — reused... instead of hardcoding a hex").

## Motion & Interaction Contract

This is the actual design contract this phase must satisfy. All values below are **locked** (from `04-CONTEXT.md` D-01–D-11 and `ROADMAP.md`'s Phase 4 success criteria) unless explicitly marked "Discretion."

### 1. Scroll reveal (ANIM-01 — already locked by ROADMAP success criterion 1)

| Parameter | Value |
|-----------|-------|
| Mechanism | Single `IntersectionObserver` instance, observes every `[data-reveal]` element (markup already shipped, no changes) |
| `rootMargin` | `0px 0px -8% 0px` |
| `threshold` | `0.08` |
| On intersect | Add `.is-revealed` class (CSS already defined in `base.css`), then `unobserve` that element — never fires twice per element |
| Fallback | `setTimeout(2600)` from module init — reveals every `[data-reveal]` element unconditionally, then `io.disconnect()` |
| No-IO fallback | `if (!('IntersectionObserver' in window))` → reveal all immediately |
| DOM mutation method | **Class toggle only** (`classList.add('is-revealed')`) — never write `el.style.opacity`/`el.style.transform` directly from JS; the shipped CSS in `base.css` already owns the visual transition (`opacity`/`transform`, `--dur-reveal` = 0.7s, `--ease-out` = `cubic-bezier(0.22, 1, 0.36, 1)`) |
| Reduced-motion behavior | No JS branching needed — `base.css`'s `@media (prefers-reduced-motion: no-preference)` wrapper around the hidden pre-reveal state means the IO/timeout logic can run unconditionally; under reduced-motion the class toggle is visually a no-op (content is already at `opacity: 1` per the unwrapped `[data-reveal]` rule) |

### 2. Cursor glow (ANIM-03, D-01–D-05)

| Parameter | Value |
|-----------|-------|
| Scope | Whole page — `position: fixed`, not scoped to hero. New DOM element in `BaseLayout.astro`, renders on every page (landing, `/obrigado`, `/politica-de-privacidade`, `/404`) |
| Size | 640×640px, `border-radius: 50%`, `margin: -320px 0 0 -320px` so the element's own top-left tracks the cursor and the circle centers on it |
| Gradient | `radial-gradient(circle, rgba(108, 76, 255, .28) 0%, rgba(108, 76, 255, .10) 38%, rgba(108, 76, 255, 0) 68%)` — exact stops, do not reinterpret through nearby existing tokens (`--color-accent-glow` etc. use different alpha values and must NOT be substituted here) |
| Blend mode | `mix-blend-mode: screen`, **unconditional** — including over light sections (Diferenciais, Contato). No per-section override, no reduced opacity on light backgrounds. If it reads as washed-out there, that is accepted as faithful to the design (D-04), not a bug to fix |
| Positioning update | `pointermove` (passive listener) → single-flight `requestAnimationFrame` write of `el.style.transform = 'translate3d(Xpx, Ypx, 0)'` (rAF-throttle idiom: a `pending` boolean guard, at most one write per frame) |
| `pointer-events` | `none` |
| `aria-hidden` | `true` |
| Activation gate | Only created/attached when **both** `matchMedia('(pointer: fine)').matches` **and** `matchMedia('(prefers-reduced-motion: no-preference)').matches` are true |
| Reduced-motion / coarse-pointer behavior | Element is **not created at all** — not parked off-screen, not created-then-hidden. If either media feature fails the check, `initGlow()` returns before touching the DOM |
| Coexistence with `.hero-glow` | The new global glow element is **additive** — `HeroBleed.astro`'s existing static `.hero-glow` (non-moving, scoped to the hero) is left completely unmodified; both render simultaneously inside the hero region |
| CSS authoring constraint (SITE-04) | The glow's static styles (size, gradient, blend-mode, border-radius, position, `z-index`, `pointer-events`, `will-change: transform`) **must** be authored as a CSS class (e.g. `.cursor-glow`) in a `<style>` block or `base.css` — **never** an inline `style=""` attribute on the element (the design source's own `style="..."` authoring must not be copied verbatim; `SITE-04`'s "no author `style=\"\"` in `src/`" grep still applies to this phase's new markup). Only the per-frame `transform` position write from JS is exempt, since it is a runtime `el.style.transform` mutation, not an authored source attribute (confirmed non-issue for `security-check.sh` check 2 per `04-RESEARCH.md` SEC-07 mapping). |
| Discretion (per CONTEXT.md) | Exact blur/gradient-stop fine-tuning beyond the 640px/three-stop reference above is left to planner/executor judgment against the real Outfit/DM Sans layout — but the three locked stops and 640px size are the starting point, not a suggestion |

### 3. Particle canvas (ANIM-04, ANIM-05, D-06–D-09)

| Parameter | Value |
|-----------|-------|
| Host element | Existing `<canvas class="hero-canvas" aria-hidden="true">` in `HeroBleed.astro` — no new canvas element |
| Point-count formula (normal case) | `n = round(min(90, max(28, (w * h) / 11000)))` — exact design-source formula, unchanged |
| DPR cap | `min(1.5, devicePixelRatio)` — lowered from the design source's `min(2, devicePixelRatio)` per ANIM-05 |
| "Few cores" trigger | `navigator.hardwareConcurrency <= 4` (D-07) — note this will always be true on iOS Safari (clamped to 2) and Firefox with `resistFingerprinting` (clamped to 2); this is expected, not a bug (see `04-RESEARCH.md` Pitfall 4) |
| Small-viewport trigger | `window.innerWidth < 860` — reuse the project's one existing breakpoint convention (`tokens.css` / `SiteHeader.astro`), per `04-RESEARCH.md`'s Open Question 2 recommendation. **This is the only remaining Discretion item this spec resolves rather than leaving open** — use 860px unless the planner has a specific reason to diverge |
| Data-saver trigger | `navigator.connection?.saveData === true` — optional-chained, explicit `=== true` (never throw on Firefox/Safari where `navigator.connection` is `undefined`) |
| Reduction behavior | When **any** of the three triggers above is true, **halve** the normal-case point count (D-08) — not a switch to an unrelated fixed number |
| Point/line rendering | Mirror the design source's `particles(cv)` method: velocity `(Math.random() - 0.5) * 0.22` per axis, radius `Math.random() * 1.5 + 0.5`, connection lines drawn between points closer than `108px`, line alpha `0.16 * (1 - d / 108)`, dot fill alternates accent (`i % 4 === 0`) vs. white `.30` alpha (see Color section above) |
| Resize handling | `ResizeObserver` on the canvas re-runs `seed()` (re-reads bounding rect, re-scales for DPR, regenerates points) |
| Pause/resume (ANIM-04) | Dual-gate pattern: one `IntersectionObserver` (canvas in/out of viewport) + one `document.hidden`/`visibilitychange` listener, both routed through a single `syncLoop()` that starts/stops exactly one `requestAnimationFrame` id — never two independent start/stop code paths for the same loop (see `04-RESEARCH.md` Pattern 3 for the exact anti-pattern to avoid) |
| Reduced-motion fallback (D-09) | Renders a **single static frame** — seed once, draw once, no `requestAnimationFrame` loop at all, no IO/visibility listeners needed since there is no loop to pause. This is checked once at init (not per-frame) |
| Frame-loop cost discipline | Reuse the same `pts` array in place inside `tick()` (no per-frame allocation); this is the primary lever against the TBT budget per `04-RESEARCH.md` Pitfall 2, since the hero canvas starts its loop immediately on load, inside the Lighthouse measurement window |

### 4. Reduced-motion contract (cross-cutting, ANIM-05/06/09)

| Signal | Behavior |
|--------|----------|
| Scroll reveal | No JS branch needed — CSS-gated no-op (see §1) |
| Cursor glow | Fully disabled, element never created (D-05) |
| Particle canvas | Single static frame, no rAF loop (D-09) |
| `dmFloat` / `dmPulse` keyframes | Already stopped by Phase 3's blanket `@media (prefers-reduced-motion: reduce)` rule in `base.css` (lines 97–109) — Phase 4 introduces no new consumer of these keyframes and must not reintroduce animated properties outside that guard |
| Layout-triggering properties | None of this phase's effects animate width/height/top/left/margin/padding — glow uses `transform` only, canvas draws are `<canvas>` 2D paints (not layout), reveal uses `opacity`/`transform` only (already true of the shipped CSS) |
| Parallax / scroll-jacking / preloader | None exist and none are introduced — out of scope per `REQUIREMENTS.md`'s Out-of-Scope table and `04-CONTEXT.md`'s explicit non-scope list |

### 5. Script architecture (D-10, D-11 — implementation detail, included here because it constrains where/how the above visuals are wired up)

| Script | Type | Location | Why |
|--------|------|----------|-----|
| `.js-ready` toggle | `<script is:inline>` — exactly `document.documentElement.classList.add('js-ready')`, nothing else | `BaseLayout.astro` `<head>` | Must run synchronously pre-paint; a normal Astro `<script>` is auto-`type="module"` (deferred), which would cause a flash of visible-then-hidden reveal content (`04-RESEARCH.md` Pitfall 1) |
| Reveal + glow + canvas | One bundled `<script type="module">` importing from `src/scripts/` | End of `BaseLayout.astro` `<body>` (or an Astro `<script>` block co-located with a component — planner's choice, must stay a single bundle) | Single-bundle requirement per `CLAUDE.md`; ANIM-04's "`client:visible` island" is satisfied by the canvas's own internal IntersectionObserver pause/resume, not a literal framework directive (no UI framework installed) |

Zero comments in any versioned script file (project-wide D-04 from Phase 1 CONTEXT). Zero new npm dependencies — see `04-RESEARCH.md` Standard Stack (confirmed: no package is appropriate for ~150 lines of IO/rAF/canvas code).
