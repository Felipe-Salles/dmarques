<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| human decision → repo content | Felipe's approval is the only gate for claims that no script can validate: brand accuracy, alt-text honesty, and whether a portfolio claim is truthful. |
| human decision → security posture | The SEC-07 judgement items and the finding dispositions are accepted by a named human; the script only produces the mechanical evidence. |
| build output → visitor | Re-verified after the edits so an approved copy change cannot ship a broken build. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-17 | Spoofing | published portfolio claims | mitigate | Task 1 forces a human to confirm `rotulo: projeto próprio` and to check every `resultado` metric against the measured numbers in `.planning/security/runs/phase-01.md`. An unverifiable marketing claim cannot ship on Claude's judgement alone. |
| T-02-18 | Tampering | approved copy breaking the schema | mitigate | Task 3 re-runs `pnpm run check` and `pnpm build` after applying edits, and the acceptance criteria restate the `cases` min/max bounds so a too-short replacement string is caught before commit rather than in CI. |
| T-02-19 | Elevation of Privilege | a High finding downgraded to close the phase | mitigate | Task 3 explicitly forbids downgrading a High and requires a stop-and-report instead; the acceptance criteria grep the run file for any `High`+`Open` row, and `SECURITY-CHECKLIST.md` and `security-check.sh` must stay unmodified (asserted via `git status --porcelain`). |
| T-02-20 | Repudiation | unattributed sign-off | mitigate | The appended block names the approver (`Felipe Salles`) and the date, inside a file that already pins the reviewed commit SHA, and the verbatim decision is duplicated into `02-04-SUMMARY.md`. |
| T-02-21 | Information Disclosure | alt text or copy leaking internal detail | accept | All reviewed strings are public marketing copy about the maintainer's own site; there is no client name, credential or internal system referenced. Felipe's read in Task 1 is the control. |
| T-02-SC | Tampering | npm/pnpm installs | mitigate | **Zero packages installed.** Any cover regeneration reuses the Sharp bundled inside `astro@7.3.1`; `git status --porcelain` on `package.json` and `pnpm-lock.yaml` must print nothing, and `security-check.sh` check 1 re-runs `pnpm audit --audit-level=high`. No `[ASSUMED]` / `[SUS]` package exists, so no legitimacy checkpoint is required. |

No High-severity threat is introduced by this plan. Its entire purpose is to stop Phase 2 from closing on machine judgement alone.
