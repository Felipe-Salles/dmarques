# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This is a **design-to-code conversion contract**, not a from-scratch design. The
visual source of truth is `arquivos de design/Dmarques Landing.dc.html` (Hero
"03 Bleed" variant only, lines ~147-195, plus Serviços/Processo/Diferenciais/
Sobre/Contato/FAQ/CTA-final/Rodapé, lines ~197-473). Every value below either
carries forward an existing `src/styles/tokens.css` token, corrects one per the
computed contrast math in `03-RESEARCH.md`, or locks a "Claude's Discretion"
item flagged open in `03-CONTEXT.md`. Nothing here invents a new visual
language — Phase 1 already shipped the token system; this phase's job is
fidelity + accessibility, not redesign.

## Spacing Scale

Already established in `tokens.css` (rem-based, all multiples of 4px). This phase reuses it as-is — do not add new spacing tokens.

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-label gaps, badge padding |
| `--space-2` | 8px | Compact stacks (label + input gap) |
| `--space-3` | 12px | Card internal gaps, nav link gaps |
| `--space-4` | 16px | Default element spacing, form field padding |
| `--space-5` | 20px | Card padding (small), differentiator tile gaps |
| `--space-6` | 24px | Section-internal column gaps |
| `--space-8` | 32px | Layout gaps between major blocks |
| `--space-10`–`--space-24` | 40–96px | Section-to-section rhythm |
| `--space-section` | `clamp(5rem, 9vw, 8.125rem)` | Vertical section padding (all 9 sections use this) |
| `--space-gutter` | `clamp(1.25rem, 4vw, 3.5rem)` | Horizontal section padding |

**Why the scale extends beyond the canonical 4/8/16/24/32/48/64 set:** `--space-3` (12px), `--space-5` (20px), and the `--space-10`–`--space-24` range (40–96px) fill in extra stops between and beyond the canonical values. Every one of them remains strictly 4px-aligned (a multiple of 4) — this is additional granularity for card gaps and section-to-section rhythm inherited from the Phase 1 token system, not a break from 8-point discipline. This is a documentation gap being closed here, not a design defect; no non-4px-aligned value exists anywhere in `tokens.css`.

**Exceptions this phase:**
- The mobile nav `<summary>` hamburger trigger must have a **minimum 44×44px hit area** (pad the icon with `--space-3`/`--space-4` as needed) even though the design's icon glyph itself is smaller — this is a touch-target accessibility floor (A11Y-04), not a token change.
- `--nav-height` (used by `scroll-margin-top`, see Anchor Nav Contract below) does not exist yet as a token. Add it to `tokens.css` once the header component's real rendered height is measured — do not guess a placeholder and forget to revisit (flagged as Open Question 3 in `03-RESEARCH.md`).

### Contrast remediation — exact values to apply (A11Y-06, A11Y-03)

Per D-13 (calculate-and-apply, no per-value sign-off) and D-14 (fix specific uses, not the base accent). These are computed in `03-RESEARCH.md` Pitfall 2/3 against this project's actual backgrounds — apply them exactly, then re-verify with the contrast-solver script in `03-RESEARCH.md` § Code Examples before committing any token edit.

| Token / usage | Current | Fix | Reason |
|---|---|---|---|
| `--color-text-faint` | `rgba(255,255,255,.45)` | **`rgba(255,255,255,.47)`** | Fails 4.5:1 by a hair (4.46–4.49) on all three dark backgrounds. Raising uniformly (rather than auditing every usage's font size) removes ambiguity — no perceptible visual change. |
| `--focus-ring` | `0 0 0 3px rgba(108,76,255,.5)` | **`0 0 0 3px var(--color-accent)`** (fully opaque) | The 50%-alpha ring fails 3:1 on every background in the design (1.78–2.12). Opaque `--color-accent` passes everywhere (3.86–5.10). Do not substitute `--color-accent-light` here — it fails 3:1 against light backgrounds. |
| `#6C4CFF` used as **small text** (eyebrows/labels <18.66px bold) on dark backgrounds | raw hex, e.g. Serviços "O que fazemos" (line 200), Sobre "Quem faz" (line 317), FAQ "Perguntas frequentes" (line 392) | **switch to `var(--color-accent-light)`** (`#9A85FF`) | Fails 4.5:1 (3.4–3.99) at small text sizes. `#9A85FF` passes (5.94–6.95). Hero/Processo/Contato eyebrows already use `#9A85FF` in the design source — extend the same treatment to the three instances still on raw `#6C4CFF`. |
| `#6C4CFF` used as **large text** (H1 "funcionar melhor", H2 second-line spans, CTA-final "sólido", Contato "seu projeto") | raw hex | **no change** | Qualifies for the 3:1 large-text exception; passes (3.41–3.99) on all three dark backgrounds. |
| `#6C4CFF` used on the **light** Diferenciais eyebrow (line 279) | raw hex | **no change** | Passes 4.5:1 against `#F2F3F6` (4.599) even as small text — light-background math differs from dark. |
| `--color-light-text-faint` `#767C8E` used as **small body text** (Contato form helper "Resposta no mesmo dia útil", 13.5px, line 364) | `#767C8E` (3.75:1 — fails) | **switch this specific usage to `var(--color-light-text-muted)`** (`#565C6E`, 6.0:1) | Same philosophy as D-14: fix the specific failing use, don't touch the base token globally (it may still be legitimate at large-text sizes elsewhere). If no large-text use of `--color-light-text-faint` exists in the final markup, the planner may instead darken the token itself to ~`#6B7184` (computed candidate, ≥4.5:1) — verify either path with the contrast-solver script. |
| One-off literal `#9096A8` (Diferenciais H2 span "com a gente", line 280 — **not a token**) | `#9096A8` (2.66:1 — fails even the 3:1 large-text bar) | **replace with `var(--color-light-text-muted)`** (`#565C6E`, 6.0:1) | Never a token; reuse the existing passing token rather than inventing an intermediate for a single use. |

All other existing `--color-text*` tokens (`--color-text-strong` .92, `--color-text` .82, `--color-text-muted` .66) already pass and need no change.

## Mobile Navigation Contract (SITE-06, D-04/D-05/D-06)

- **Pattern:** native `<details class="nav-toggle">`/`<summary>` disclosure, per `03-RESEARCH.md` Pattern 2 (verbatim marker-removal CSS required — both `list-style: none` on `summary` **and** `summary::-webkit-details-marker { display: none }`, not one or the other).
- **Panel style (discretion, locked here):** full-width dropdown panel anchored below the header (`position: absolute; top: 100%; left: 0; right: 0`), not an inline expanding list — keeps the collapsed header height stable and matches the design's minimal wordmark-only aesthetic better than pushing page content down.
- **Trigger:** icon-only hamburger (3-line SVG, `aria-hidden="true"` on the `<svg>`, `aria-label="Abrir menu de navegação"` on `<summary>`), no visible "Menu" text (D-06). Minimum 44×44px hit area (spacing exception above).
- **"Pedir orçamento" CTA stays outside the `<details>`**, rendered as a sibling pill button, always visible on mobile (D-05).
- **Open/close transition:** `opacity` + `transform: translateY(-8px → 0)`, duration `--dur-mid` (250ms) or `--dur-slow` (300ms max — ANIM-07 budget), `--ease-out`; wrapped in `@media (prefers-reduced-motion: no-preference)` — under reduced-motion the panel simply appears/disappears with no transition.
- **Known accepted limitation:** no outside-click dismissal (native `<details>` constraint, zero-JS). Accepted per D-04; does not violate SITE-06 (keyboard operability + no focus trap only).
- **Critical layout constraint (Pitfall 4):** never wrap the header in a shared `overflow:hidden`/`overflow-x:clip` ancestor with the rest of the page — the design's page-level `overflow-x:clip` wrapper must be scoped narrowly to the hero/canvas/glow containers that actually need it, or the expanded mobile panel will be clipped.

## Interaction States Contract (ANIM-07)

Every `:hover` rule in every component must ship with an identical `:focus-visible` rule on the same selector (never hover-only). Transitions are restricted to `transform`, `opacity`, `box-shadow`, `border-color` — never layout-triggering properties (`width`, `height`, `top`, `margin`, etc.) — and capped at `--dur-slow` (300ms). Use `--dur-fast` (200ms) for nav links/small text color changes, `--dur-mid`–`--dur-slow` (250–300ms) for card border/shadow hover states, matching the design source's own timing.

Example pattern (from `03-RESEARCH.md`):
```css
.nav-link {
  color: var(--color-text-muted);
  transition: color var(--dur-fast) var(--ease-standard);
}
.nav-link:hover,
.nav-link:focus-visible {
  color: var(--color-text-strong);
}
```

Focus ring on every interactive element uses the corrected `--focus-ring` token (see Contrast remediation table above) with `--focus-ring-offset` (2px).
